# Prompt 区只读定位与用户误会

> 为什么 Prompt 区不能再像输入框，用户误会点在哪里，只读提示怎么设计更自然

---

## 一、为什么 Prompt 区不能再像输入框

### 产品卖点

产品卖的是**结构**，不是又一个 prompt 编辑器。

若用户要靠改 prompt 才能出好结果，说明前面的结构和策略层没做好。

### 正确层级

| 主定位 | 非主定位 |
|--------|----------|
| 编译结果预览 | 不鼓励直接在这里主编辑 |
| 导出结果观察 | 不替代 Template / Director / Camera / Lighting |
| 冲突验证区 | 不承担创作主路径 |

---

## 二、用户误会点

### 1. 文本框 = 可编辑

用户看到大段文本框，会天然认为：

- 这里可以编辑
- 这里是主创作区
- 这里改了就最有效

### 2. 主创作区错觉

会把「改 prompt」当成主路径，从而削弱：

- 模板
- 对象属性
- 场景策略
- 镜头语言
- 光与氛围
- Platform / Export 策略

### 3. 结构被绕过

直接改 prompt 会：

-  bypass 结构化逻辑
- 导致后续模板/策略变更时冲突
- 不利于平台适配和导出一致性

---

## 三、只读提示怎么设计更自然

### 不推荐

- 只写「不可编辑」：生硬
- 藏在 tooltip：看不见
- 只写一行灰字：容易被忽略

### 推荐：组合式提示（方案 A）

标题下方一行轻提示：

> 这是系统根据模板、对象和场景策略自动生成的结构化提示词，仅用于查看、复制与导出。

右侧再补：

> 如需修改，请前往：模板、对象属性、场景策略、镜头/光

### 简洁版备选

- **方案 B**：只读预览，请通过上方结构模块修改
- **方案 C**：自动编译结果｜只读｜修改请返回结构层

### 实施原则

- 明显但不刺眼
- 不藏在 tooltip
- 提供修改方向的跳转（模板、对象、策略、镜头）
