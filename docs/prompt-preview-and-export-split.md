# Prompt 区与导出区左右分屏设计

> 为什么要左右分屏，为什么左边只读、右边放导出动作，为什么这比原来顺

---

## 一、为什么要左右分屏

### 原状问题

原先「提示词展示」和「导出动作」混在同一区块：

- 用户看到大段文本，不清楚这是「看结果」还是「做操作」的主入口
- 复制、导出入口藏在项目菜单或零散位置
- 心智负担：先理解模式，再找动作

### 左右分屏后的心智模型

- **左栏**：结果 —— 结构化提示词展示（只读）
- **右栏**：动作 —— 生成与导出

用户一眼可区分：

- 左边是「看」
- 右边是「拿走」

---

## 二、为什么左边必须只读

### 本质定位

该区域的本质是：

- **结构化结果** → 编译结果 → 平台导出前的预览层

不是：

- 手写 prompt 的输入层

### 若可编辑会产生的问题

- 用户会误以为「在这里改最有效」
- 削弱模板、对象属性、场景策略、镜头、光等真正该编辑的地方
- 破坏结构化编译逻辑

因此左边只负责「展示」，不负责「编辑」。

---

## 三、为什么右边放导出动作

### 用户真实行为

用户最常用的是：

1. 复制提示词
2. 导出提示词 + 参考图

而不是在展示区阅读大段 prompt。

### 动作前置

把「复制」「导出」做成右栏主按钮后：

- 无需先理解「模式」
- 直接给动作，符合「看完就拿走」的路径

---

## 四、为什么这比原来顺

### 理想工作流

1. 套模板
2. 改对象 / 策略 / 镜头 / 光
3. **左边**看结果是否合理
4. **右边**一键复制或导出
5. 去生成 / 继续生成

### 原先容易出现的偏差

1. 套模板
2. 看到一个像编辑器的大框
3. 误以为要在这里改
4. 搞乱结构
5. 再导出

分屏 + 只读 + 导出前置，让用户自然回到「结构优先、结果预览、快速拿走」的路径。
