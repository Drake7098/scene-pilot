# 导出主动作重构

> 为什么「复制提示词」和「导出提示词+参考图」要做成主按钮，为什么完整项目包下沉，文件格式选择理由

---

## 一、为什么「复制提示词」要做成主按钮

### 使用频率

复制提示词是最高频动作，用户需要快速把当前编译结果贴到其他平台。

### 心智

- 先看（左栏预览）
- 再拿（右栏复制）

主按钮化后，用户无需进菜单或弹窗，即可完成主要操作。

---

## 二、为什么「导出提示词+参考图」要做成主按钮

### 典型场景

用户需要把提示词和参考图一起带走，用于 fal、Runway 等平台。

### 与「仅 prompt.txt」的区别

- **prompt.txt 单独导出**：适合快速试方向
- **prompt + 参考图 ZIP**：适合正式交付、平台上传

后者是「拿走即用」的完整包，应作为第二主动作。

---

## 三、为什么完整项目包下沉

### 使用频率

完整项目包（含 project.json、多分镜）用于交接、存档、复用，属于低频操作。

### 层级原则

- **主按钮**：复制、导出 prompt+refs
- **次级**：更多导出 → 完整项目包、下载 prompt.txt、导出连续序列、高级设置

下沉到「更多导出」可减少主界面干扰，同时保留能力。

---

## 四、文件格式选择理由

### 1. 复制提示词

- 不下载文件，直接复制到剪贴板

### 2. 导出提示词（单独）

- 格式：`.txt`
- 仅包含 prompt 文本

### 3. 导出提示词 + 参考图

- 格式：`.zip`
- 建议结构：

```
project_scene_prompt_refs.zip
  prompt.txt
  refs/
    ref-01.png
    ref-02.jpg
  manifest.json
```

### 4. 完整项目包

- 格式：`.zip`
- 建议结构：

```
project_full_bundle.zip
  project.json
  prompt.txt
  refs/
  manifest.json
```

---

## 五、与 Platform / Export 的联动

- Platform Mode 影响左栏编译结果与右栏导出方式
- Export Scope（当前分镜 / 连续序列）影响导出的 prompt 和 refs 范围
- 主按钮使用当前平台与范围，无需每次弹窗选择
