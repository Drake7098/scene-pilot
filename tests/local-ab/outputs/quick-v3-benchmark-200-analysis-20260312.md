## 4. 关键问题分布（重点）

### 4.1 视频结构与镜头数冲突（核心阻断）
- 现象：`镜头结构=多场景/多机位/连续`，但 `镜头数量=1`
- 统计（视频100）：
  - 结构-镜头数真实对齐率：50%
  - `多结构 + 1镜头`：50/100
- 影响：直接削弱“结构化价值”，用户感知为“伪专业拼接”。

### 4.2 主场景误判为室内
- 现象：用户写“街道/森林”等室外语义，提示词仍给 `主场景 室内`
- 统计（视频100）：40/100
- 影响：场景语义反向，生成质量显著下降。

### 4.3 对象幻觉（door）
- 现象：用户未提“门/door”，关键对象仍频繁出现 `door`
- 统计（视频100）：75/100
- 影响：生成无关物体，破坏构图与语义可信度。

### 4.4 镜头语法误配（POV误注入）
- 现象：用户未要求主观镜头，却输出 `POV/主观视角`
- 统计（视频100）：32/100
- 影响：运镜偏差，结果与意图不一致。

### 4.5 图片链路专业度问题（被现有评分低估）
- 错误场景模板化（非产品需求却写成产品展示场景）：40/100
- 关键对象字段句子泄漏（整句灌入对象列表）：30/100
- 性别/主体幻觉：10/100
- 狼等关键主体丢失：20/100

### 4.6 模板尾句过强（视频）
- 现象：结尾固定句几乎完全一致
- 统计（视频100）：100/100
- 影响：专业表达单一，风格僵硬，用户感知“机器味重”。

## 5. 根因定位（代码层）

### 根因A：视频主场景被硬编码为 indoor
- 文件：`src/utils/structureDraftGenerator.ts`
- 点位：`mainScene: "indoor"`
- 后果：室外语义无法传递。

### 根因B：对象抽取词表过粗 + 回退策略过松
- 文件：`src/utils/structureDraftRules.ts`
- 问题：`PROP_TERMS` 含 door 等通用词，二段文本/提示词语法词会误入对象集合。
- 后果：`door` 幻觉、对象列表失真。

### 根因C：镜头数可与结构类型冲突
- 文件：`src/components/quick-workspace/QuickWorkspaceSecondaryCards.tsx`
- 问题：多场景/多机位下仍允许选 `1`。
- 后果：产生“多结构+单镜头”矛盾提示词。

### 根因D：V3拼装层缺少一致性二次校正
- 文件：`src/utils/quickWorkspacePromptV3.ts`
- 问题：直接拼装，不做结构约束修正（如多场景至少2镜头、主场景纠偏、对象去噪）。
- 后果：异常值直接进入最终提示词。

## 6. 修复优先级（按收益排序）

### P0（立即修）
1. 结构-镜头数强约束
- 规则：
  - `single_shot => shotCount=1`
  - `multicam/continuous/multi_scene => shotCount>=2`
- UI联动：对应结构类型时禁用不合法shotCount选项。

2. 主场景推断替代硬编码
- 从 step1+step2 提取 indoor/outdoor/complex/multi_scene。
- 未命中时再 fallback，不直接固定 `indoor`。

3. 关键对象净化
- 过滤镜头语法词（door/cut/pov/reverse 等语法注入词）
- 对象必须来自“名词候选 + 置信度阈值”。

### P1（下一轮）
4. 视频模板去僵化
- 将固定结尾改为结构相关可变句，按 `structureType + continuityFocus + shotGrammar` 组合。

5. 图片对象抽取修正
- 避免整句进入 key objects；限制对象名长度与词性。

### P2（验证与守门）
6. 评测守门升级
- 新增硬门槛：
  - 视频结构-镜头对齐 ≥ 95%
  - 主场景语义一致 ≥ 90%
  - 对象幻觉率 ≤ 5%

## 7. 当前是否可用于“专业级”
- 结论：**不建议现在宣称专业级视频提示词**。
- 原因：视频结构一致性仅50%（真实对齐），且对象/场景幻觉仍高。
- 图片可用性明显更好，但“对象抽取质量”和“模板化”还需收敛。
